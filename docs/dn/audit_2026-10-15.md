# DN 活性與動作梯度檢查

檢查日期：2026-10-15。結論：確實存在 DN 全部沉默、動作任務梯度被 ReLU 阻斷的實例；建議列為 P1，在正式長時間訓練前處理。並非所有初始化或 smoke 模型都已有六個 DN 全零。

本次只產生診斷檔案，沒有修改模型、訓練程式、設定或 checkpoint。

## 實測範圍

- 真實中央圖：2569 個神經元、14165 條邊，指定運動讀出為 DNa01、DNa02、DNp09 各左右一個，共六個。
- 使用現有官方匯出視覺前端及四段已錄製的視覺預訓練資料，每段前 256 個控制步；另加入只交換左右眼影像的配對輸入，保留其他觀測。每個模型共 2048 個步／lane。
- 配對影像確實改變前端輸出：最大視覺 code 差異 0.29059586。感覺前端有響應，不能把動作無變化歸因於測試輸入相同。
- 動作梯度探針：先以原輸入 burn-in 64 步，再對 32 步的非零動作誤差反向傳播；不加入 activity regularizer，分辨動作學習是否有梯度。

| --- | ---: | ---: | ---: | --- |
| 新建 VO | 3/6 | 2.02e-6 | 3.66e-7 | 非零 |
| 現有 128 步 PPO smoke VO | 4/6 | 1.00e-5 | 7.77e-7 | 非零 |
| 現有 V 視覺預訓練 checkpoint | 0/6 | 0 | 0 | 全零 |

V checkpoint 已收集 240000 個環境步；已完成第一個 epoch，第二個 epoch 的 checkpoint 位於第 7000/7600 個 window。它尚未完成完整預訓練。完整第一個 epoch 的輔助 loss 為 0.00380755，但六個 DN 已全部沉默。

## 直接原因與程式證據

1. `python/flytrack_core/model/policy.py` 的 `MaskedRateCore.forward` 使用 `relu(voltage)` 傳遞 recurrent 電流；`ConnectomePolicy.forward_code` 又對最終中央電位取 ReLU，才交給 `MotorReadout`。負電位在這兩處都輸出零。
2. 讀出只使用 DN 的活性。結構讀出的轉向為 `omega_max * tanh(turns @ turn_weight)`；六個 DN 為零時，轉向均值必為零。速度只剩 `v_max * sigmoid(forward_bias)`；此 checkpoint 的 bias 為零，故固定為 0.25 m/s。
3. 此 checkpoint 的 DN bias：DNa01 = -0.00600547、DNa02 = -0.01689210、DNp09 = -0.00600545。所有探針步的 DN 電位均為負，最大電位仍不高於約 -0.006。
4. 實測動作損失對 `core.raw_alpha`、`core.raw_tau`、`core.bias`、`readout.turn_weight`、`readout.forward_weight` 的梯度全部為零。速度的 `forward_bias` 仍能更新，因此不能說整個 optimizer 完全停止。
5. 視覺預訓練以另一個可丟棄的 `Linear` decoder 讀出整群 visual/convergence 活性（`python/flytrack_train/pretrain.py`），沒有要求資訊必須經由運動讀出。依本圖的 group mask，六個 DN 都包含在視覺 decoder 的輸入群裡，但 decoder 可以使用其他神經元，並不需要使用 DN。因此低輔助 loss 不代表 DN／動作路徑正常。
6. 額外的輔助 decoder 誤差與設定中的 activity penalty 探針顯示：其他中央 bias 有梯度，但 DN 的 bias、tau、以 DN 型別為目標的 alpha 梯度仍全為零。這是「已沉默的 DN 沒有直接修復訊號」的證據；沒有做完整訓練消融，不能據此斷言某一個 loss 項單獨造成沉默。

ReLU 定義及 autograd 語意參照 [PyTorch 2.9 ReLU](https://docs.pytorch.org/docs/2.9/generated/torch.nn.ReLU.html) 與 [Autograd mechanics](https://docs.pytorch.org/docs/2.9/notes/autograd.html)。上述梯度零的結論也由本機 PyTorch 2.9.1 實測確認。

## 原始版本與干預驗證

- 直接載入 `git show HEAD` 的原始 `policy.py` 及原始 `frontend.py`，再載入相同 V checkpoint，重播四段資料各 128 步：六個 DN 仍全部為零，動作固定 `[0.25, 0]`。這確認目前的加速／快取修改不是產生此現象的必要條件；本次沒有從頭重跑原始版本的完整訓練。
- 所有六個 DN 都有可從感覺種子到達的興奮性路徑；拓樸連通不等於實際活性／梯度能通過。
- 反事實探針：將同一組 V 權重放入 VO 架構，讓嗅覺 ORN response 分別固定為 0、0.01、0.5、1，並標記嗅覺有效，六個 DN 仍全零。這是壓力測試，不是已訓練 VO 的實測結論。
- 只在記憶體中將三個 DN 型別 bias 設為 0.01，保留其餘權重，六個 DN 恢復活性；交換左右眼後最大角速度差為 0.00026096 rad/s，轉向損失對 alpha/tau/bias/turn weight 恢復非零梯度。只把 bias 重設為 0 則仍全零。這支持負電位／dead ReLU 的診斷，但正 bias 尚未經完整訓練驗證，也不代表已得到足夠強的控制能力。

## 嚴重程度與處理建議

- **P1／高嚴重度**：影響核心研究功能與後續訓練有效性。應在大量種子及長時間正式訓練前處理。
- **對 BC／DAgger／PPO 的影響**：當所有動作 DN 都維持負電位時，行為誤差或 policy gradient 無法透過運動讀出修復中央網路。PPO 的 critic、探索標準差及速度 bias 仍能學習；隨機採樣仍可能產生轉向，不能把探索動作誤判為視覺控制。
- **不能保證長訓練自行修復**：其他活躍神經元仍可由輔助 loss／activity penalty 改變，或不同感覺輸入使 DN 跨過零，所以沒有證明永久不可恢復。但目前缺乏可靠的恢復機制，不能以增加步數作為修復保證。
- **優先驗收**：在預訓練、BC、PPO 的階段交界，用真實圖與左右／運動視覺刺激檢查每個 DN 的正活性比例及電位、視覺干預對轉向的影響、單獨動作任務的中央梯度。數值應超過浮點誤差並有合理的控制幅度；僅檢查 loss、張量形狀或梯度 Tensor 存在不足。
- **修正方向**：評估可維持 DN 工作點的 bias 設計，或保留非負放電率且在負電位仍有梯度的平滑 rate function；同時避免預訓練完成時留下無效的運動路徑。須用小規模端到端訓練驗證，所有連接體比較變體採一致方案並重驗動態穩定性。單純改成 linear DN readout，若輸入仍是六個零活性，也不會解決問題。
- **研究結論限制**：目前只有 smoke VO 與未完成的 V 預訓練 checkpoint；沒有完整訓練 VO／VO-late／RS 的產物。本報告不宣稱所有變體或所有種子最後都會失敗。
