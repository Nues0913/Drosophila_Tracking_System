# WP3c 中央核心、DN 讀出與感覺編碼 v2（Issue #136）

六個變體共用 [Policy 介面](interfaces.md#5-policy)，預設設定見 [default.yaml](../../configs/v2/model/default.yaml)。`build_policy` 可傳入已驗證的 `GraphV2` 和固定的 `InputNorm`。`describe()` 提供模型設定、狀態尺寸、正規化擬合狀態及有效參數數量。圖策略也列出速度和轉向讀出實際使用的型別與各側 bodyId。

## 中央核心

令 `t(i)` 為神經元 i 的型別，`s_j` 為突觸前神經元 j 的號誌，`n_ij` 為邊上的突觸數，`N_i` 為 i 在子圖中的輸入突觸總數。

```text
τ_t(i) · dv_i/dt = −v_i + b_t(i) + Σ_j W_ij · r_j + I_i
r_j = softplus(v_j, beta=10)
W_ij = s_j · (n_ij / N_i) · g[label(j→i)]
```

- `g` 按邊使用的型別對標籤共享，預設為 `softplus(θ_g)`，初始化為 0.9。有輸入的列在初始化時絕對權重總和為 0.9，無輸入的列為 0。訓練可使預設增益超過這個界限。選用 `bounded` 時使用 `gain_max · sigmoid(θ_g)`，預設上界 0.97 適用於整段訓練。
- `τ = min(τ_min + softplus(θ_τ), τ_max)`，按在圖中出現的型別共享。用 `init_seed` 在 0.02–2 s 之間對數均勻初始化，下界 0.01 s，上界 10 s。
- `b` 按型別共享，初值為 0。完整計算靜息狀態時，核心從當前的 `b_t(i)` 開始演化。預設 bias 學習率為基準的 0.1 倍，設為 0 時凍結並從有效參數表排除。
- 每個 0.05 s 控制步有五個 0.01 s 子步，保持外部輸入 `I` 固定。每個子步使用開頭電位計算活動，再做指數 Euler 更新。

```text
α_i = exp(−Δt / τ_t(i))
v_i ← α_i · v_i + (1 − α_i) · (b_t(i) + Σ_j W_ij · r_j + I_i)
```

CSR 依 `(post, pre)` 排序，結構為 int32，權重值每控制步計算一次。子步以 `[N, B]` 運算，反向以轉置 CSR 求活動梯度。CUDA 用 `torch.sparse.sampled_addmm`（SDDMM）只計算 CSR 樣式內各邊的點積，重複使用全零的樣式值 buffer，並按 CSR 的 `(post, pre)` 順序回傳權重梯度。PyTorch 2.9.1 的 CPU SDDMM 會將 CSR 索引轉成 int64，因此 CPU 用分塊 gather 計算點積，塊大小依 batch 調整。CUDA 的 float16 和 bfloat16 也使用分塊 gather。

依計劃書 0.2，activation checkpoint 預設關閉。只有在主機記憶體不足（例如使用 6 GB 顯示卡）且經 PM 同意時才開啟。開啟後，有梯度的前向會以非 reentrant checkpoint 包住每個控制步的五個子步，反向時重算其中間值。無梯度推論直接執行。

下表是 VO2 在 4060 上執行 80 步序列前向與反向的結果，量測方式見[效能驗證](#效能驗證)。

| 64 | 開 | 480 | 0.89 GB |

## DN 讀出

主圖預設從萃取時標記的 turn／forward 群選擇轉向讀出，包括成對的 DNa01、DNa02、DNa03、DNb05、DNp09，速度讀出採用 forward 群的 DNp09。先對每顆 DN 的速率做正規化，再按型別和側別計算平均。轉向取左減右，速度取左加右。`steer_types` 和 `speed_types` 可指定型別清單，轉向型別必須左右成對。

```text
σ̃_i = max(σ_i, 0.1 · median_j(σ_j))
r̃_i = (r_i − μ_i) / σ̃_i
z_ω = Σ_k a_k · (mean(r̃_k,L) − mean(r̃_k,R)) + c
z_v = Σ_m b_m · (mean(r̃_m,L) + mean(r̃_m,R)) + d
v = v_max · sigmoid(z_v)
ω = ω_max · tanh(z_ω)
```

未擬合時，`μ_i = 0`、`σ̃_i = 1`，`a_k` 和 `b_m` 預設初始化為 1，所以左側活動增加會提高轉向 latent。圖變體的每條訓練鏈用自己的初始 policy 及首輪 teacher 軌跡估計各 DN 的平均與母體標準差，以反映該鏈的感覺遮罩、核心結構和初始化。擬合後，轉向各型使用同一初始權重，速度各型也使用同一初始權重，兩維各自縮放至擬合樣本上的 latent 母體標準差為 0.1，沿用原始讀出權重的符號。擬合只做一次，讓核心後續學習時始終使用固定的讀出座標。平均、尺度及擬合旗標以 persistent buffer 保存在 `weights.pt`。GRU2 沿用線性讀出。 [#137 Decision](https://github.com/Nues0913/Drosophila_Tracking_System/issues/137)

動作潛在變數採用 `(speed, turn)` 順序，兩維的 `log_std` 都是可學、與狀態無關的參數，初值為 −0.5。

### 靜息狀態與讀出校準

中性感覺碼的原始特徵取 `input_norm.mean`，四個有效旗標皆為 1。正規化後的特徵皆為 0，有效眼仍會加上學到的視覺偏移，因此靜息狀態與讀出偏置校準都包含偏移。V2／O2 套用各自的變體遮罩，停用通道使用對應的缺失偏置。

完整計算從核心偏置狀態（圖策略的 `v = b` 或 GRU2 的 `h = 0`）開始，以中性碼呼叫 `forward_code` 逐步演化。演化時不記錄梯度，batch 為 1。步數為 `rest_settle_s / control_dt` 取整數，預設 8 s，即 160 個控制步。建構時用靜息狀態校準圖策略的 `c`、`d` 或 GRU2 線性層的兩個偏置，使動作眾數為 0.20 m/s（`initial_speed_m_s`）及 0 rad/s。

預設 `initial_state: rest` 讓回合從靜息狀態開始，避免核心在開頭的演化造成零輸入下的速度與轉向漂移。每次初始化回傳切斷梯度的靜息狀態複本。影響動態的參數更新後，下次要求初始中央狀態時，從上一次的靜息狀態接續演化 `rest_refresh_s`，預設 1.0 s，即 20 個控制步。`rest_refresh_s` 必須大於 0 且不超過 `rest_settle_s`。各次增量更新讓狀態持續接近當前動態的靜息狀態。建構、載入權重或轉換裝置／dtype 後的首次計算採用完整演化。

評估與匯出前呼叫 `refresh_rest_state(full=True)`，從核心偏置狀態完整重算並更新快取，使結果與訓練歷史無關。4060 上 VO2 完整重算的 160 步曾量得 194 ms，batch 為 1 的序列演化受 GPU kernel launch 開銷限制。增量更新把每次參數更新後的演化縮短到預設約 20 步。

初始讀出偏置依模型的初始狀態設定建構。圖變體擬合讀出正規化後，依 #168 在中性輸入的靜息狀態重新校準 `c`、`d`，使動作眾數回到 `(0.20 m/s, 0 rad/s)`。之後偏置與權重照常學習，載入權重時沿用已儲存的偏置。

### 雙側 DN 群體讀出

`speed_types: bilateral` 以主圖 manifest 的 DN 型別為候選。每型必須在子圖中剛好有一顆左側與一顆右側神經元，且兩顆的輸入覆蓋率（子圖輸入突觸數除以全腦輸入突觸數）皆至少為 0.40。主圖符合條件的 31 型及兩側 bodyId 固定在 [readout_bilateral_dn.yaml](../../configs/v2/model/readout_bilateral_dn.yaml)。

讀出按 bodyId 定位節點，並驗證來源圖的 SHA-256 和節點側別。RW2、ER2 保留主圖的節點身分，可使用同一份清單。這個選項只套用到速度讀出，轉向沿用 `steer_types`。

## 感覺碼、正規化與 seed 投射

- `sense` 驗證觀測鍵和形狀，將缺失或非有限讀數標成無效。感覺狀態包含 node-major 視覺前端 `[N_f, 2B]` 及 ORN 適應值 `[B, 2, n_odor_channel]`。回合重設只更新指定環境。這一段凍結，可在 rollout 時快取。
- 感覺碼依序放左眼、右眼、左右 ORN、左右風讀值及四個有效旗標。預設每眼 16 型 × 9 區間、每側一個 ORN 通道，共 296 欄。ORN 使用 Hill 曲線與共同適應，風採用原始觸角讀值。
- `forward_code` 使用固定的平均與母體標準差將欄位正規化，無效通道歸零，保留有效旗標。標準差下限為 `1e-3`，可限制低變異欄位的放大倍數。未擬合時使用平均 0、標準差 1，且 `fitted = False`。WP4a 以 100 回合 teacher 軌跡擬合，只用各通道的有效列；沒有有效列的通道維持初值。統計存入 `input_norm.npz`，標準差下限由模型設定提供。
- 視覺 seed 的 LC 感受野每型別、每側各有一組非負權重。同型同側的 seed 因而收到相同輸入。初始化每個特徵為 `1/144`，等分池化是工程假設。
- Teacher 駕駛時，目標通常在前方附近，`InputNorm` 以這批資料的平均值為中心。學生追蹤不佳時，目標小且偏離前方，視覺碼正規化後平均降至 −0.127，只有 6% 的視覺 seed 驅動大於 0，平均活動率為 0.034（noise 情境為 0.183）。在評估時平移 +0.14σ，curved normal 的成功率由 0.04 升到 0.84。+0.28σ 取自 noise 情境在閉環中造成的平移量，(e) 在訓練與評估都套用這個值，成功率為 0.79、碰撞率為 0.01。 [#184](https://github.com/Nues0913/Drosophila_Tracking_System/issues/184)
- 每個視覺 seed 型別（LC）有一個可學的 `visual_offset`，左右眼共用。對型別與眼睛群組 `g`，池化後的視覺驅動加上 `visual_offset[type(g)] × valid_eye(g)`。無效眼的視覺碼歸零，使用缺失偏置。感受野初始權重總和為 1，因此偏移 0.28 等效於池化前將正規化後的每個有效視覺欄位加 0.28。偏移使用完整的基準學習率，核心偏置 `b` 預設使用 0.1 倍學習率。
- 新訓練的 YAML 預設 `visual_offset_init: 0.28`，設為 `null` 即停用。舊 model card 缺少此鍵時預設為 `null`。O2 停用視覺驅動，偏移沒有梯度。GRU2 由 GRUCell 的輸入偏置學習平移。
- ORN 型別按順序以 `ordinal % n_channel` 對應通道。氣味和風依側別讀取，若為中線則平均左右。缺失時每種 seed 型別可學一個偏置，初值為 0。外部電流只投射到感覺 seed。

| 變體 | 中央結構 | 有效感覺 |
| --- | --- | --- |
| VO2 | 主圖 | 視覺、氣味、風 |
| V2 | 主圖 | 視覺 |
| O2 | 主圖 | 氣味、風 |
| RW2 | 保留側別的雙邊交換 | 視覺、氣味、風 |
| ER2 | 均勻取樣的有向圖 | 視覺、氣味、風 |
| GRU2 | GRUCell 與線性讀出 | 視覺、氣味、風 |

RW2 在相同的突觸前／後側別組內提出交換候選，依序拒絕自環和重邊。每條交換後的邊沿用突觸前一半的突觸數和標籤，節點入度、出度、號誌與每種側別對的邊數都保留。ER2 從全部有序異節點對均勻、不放回地抽取同數量的邊，再將原圖每條邊的突觸數和型別對標籤成對洗牌，每組剛好用一次。ER2 的標籤與突觸數多重集合及 `g` 個數均與原圖相同。兩個對照組都重算 fan-in，且需要明確的 `structure_seed`。

GRU2 將正規化的完整感覺碼送入 GRUCell，線性層輸出速度和轉向 latent。GRU bias 初始化為零，初始隱藏狀態與讀出校準採用上述靜息狀態。隱藏寬度選擇使正式有效參數最接近 VO2，容許差為 ±5%。

正式預算沿用 v1 #77 的定義，計入所有 `requires_grad=True` 且 optimizer 學習率大於 0 的參數。模型表以正的基準學習率計算，`bias_lr_scale=0` 時排除中央核心 bias。O2 的正式預算包含 LC 感受野與視覺偏移。O2 的兩眼恆為無效，視覺 seed 使用缺失偏置。

診斷欄 `output_reachable_total` 計算正式預算中有路徑可影響動作分布的參數。圖策略由 DN 讀出沿突觸反向追蹤，並依變體的固定感覺遮罩排除停用的視覺參數。O2 的診斷值排除 LC 感受野與視覺偏移，保留仍作用於視覺 seed 的缺失偏置。

## 匯出與載入

`flytrack_v2.model.export_policy(policy, out_dir, provenance=...)` 將 CPU 權重、實際使用的前端檔案、輸入正規化統計和感測契約分別存到 `weights.pt`、`frontend.npz`、`input_norm.npz`、`sensor_contract.json`。圖策略還寫入 `graph.npz`，保存實際的邊、邊的參數共享標籤和接線統計。匯出前以 `refresh_rest_state(full=True)` 從核心偏置狀態完整重算靜息狀態。

`model_card.json` 記錄完整的 `model_config`，包括感覺碼設定、視覺偏移初值 `visual_offset_init`、增益參數化、實際讀出型別、RW2／ER2 的結構種子，以及 GRU2 的有效參數預算和隱藏寬度。卡片保留原設定的相對路徑以供追溯。圖策略的速度與轉向讀出都按型別記錄左右兩側的 bodyId。接線後的圖匯出成新檔案時會有自己的 SHA-256，因此產物使用卡片中的 bodyId 定位讀出節點。來源圖的雜湊另存為 `graph_origin_sha256`。卡片也記錄感測契約雜湊、狀態尺寸、時序、動作限制和訓練來源。卡片的 `files` 記錄各資料檔的 SHA-256，`SHA256SUMS` 也涵蓋卡片本身。

`flytrack_v2.model.load_policy(artifact_dir, device="cpu")` 是唯一的載入入口。它先驗證檔案雜湊和卡片，再用產物目錄內的檔案和解析後的設定建構策略。圖策略直接使用匯出的接線與讀出節點，並驗證每個 bodyId 的側別。載入以權重檔中的參數還原已訓練的讀出偏置，接著完整重算靜息狀態。
